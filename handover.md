### Step 3 ported to bootstrap-app and strata-app (2026-08-24)

Same visual spec as tailwind-app (6-category Mega Menu, 4 link columns + gradient promo per category, 8-column Master Mega Footer, trust badges, rolling announcement bar + payment marquee, 3-way theme toggle) but each rebuilt using that framework's own native mechanism, not copy-pasted Alpine:

- **bootstrap-app**: Bootstrap's own `navbar` + `dropdown` (`data-bs-toggle="dropdown"`) for the mega-menu, using the documented `position-static` mega-menu trick (dropdown's parent `<li>` gets `.position-static` so the `.dropdown-menu.w-100` can span full width instead of being Popper-anchored to the toggle button). Mobile nav uses Bootstrap's `offcanvas` + nested `accordion` (`data-bs-toggle="collapse"`). Theme toggle uses a small self-hosted `public/js/theme-toggle.js` (Bootstrap ships no reactive/toggle-cycling primitive, so this thin script is the closest thing to "native idiom" available). **Before touching Bootstrap markup here, first resolve two real findings** (see Decisions below): (1) `coding-standards/frameworks/bootstrap.md` now carries a **project-wide accepted exception** for Bootstrap's `!important` utility classes and Collapse's inline-style animation — read that file's "PROJECT-WIDE EXCEPTION" block before assuming utilities are banned; (2) Bootstrap's own dark-mode CSS only activates on the **literal** `data-bs-theme="dark"` value, so the theme system splits into two attributes — `data-theme-shade` (dark/light/dim, drives our own tokens) and `data-bs-theme` (dark/light only, drives Bootstrap's internals) — see `public/js/theme-toggle.js` and the comment above the `[data-theme-shade]` blocks in `globals.css`.
- **strata-app**: `.claude/skills/strata-css/SKILL.md` was read first, per its trigger. Key finding (now in that skill's `learnings.md`): Strata core ships **no** pre-built navbar/dropdown/offcanvas/accordion component — only `data-st-visible`/`data-st-collapsed` state attributes with baked-in CSS transitions (fade / max-height-collapse respectively), which is genuinely the whole "native idiom" here. Built the mega-menu/mobile-nav/accordions entirely from Strata utility classes + these two state attributes, driven by a small self-hosted `public/js/interactions.js` (generic `data-toggle-target`/`data-toggle-attr` click handler + `data-hover-group`/`data-hover-target` hover handler + theme cycling). Unlike bootstrap-app, Strata's `data-st-theme` genuinely supports `"dim"` as a first-class value at the core CSS level — no shade-splitting workaround needed.
- Both ports needed the **same `iw-` custom-CSS classes** as tailwind-app for things no framework utility can do (gradient text/panels via `linear-gradient()` + `background-clip:text`, the `.iw-marquee`/`.iw-marquee-track` `@keyframes`, cart badge, theme-toggle pill) — kept the class names identical across all 3 apps' `globals.css` for easy comparison, with each file's actual property values/selectors adapted per-app.
- **Real bugs found and fixed during the bootstrap-app port** (the established Step-2 "cascade order" gotcha recurring in new places — `bootstrap.min.css` loads after the Next-injected stylesheet, so any custom class with equal CSS specificity to a Bootstrap class loses unless deliberately given higher specificity): footer/nav links styled only `.iw-nav-link` were rendering Bootstrap's default underline; icon buttons and the theme toggle were rendering Bootstrap's default link-blue instead of muted grey; the mobile accordion's active-state background/text was rendering Bootstrap's default blue tint instead of transparent/accent. Fixed by compounding selectors (`.form-control.iw-newsletter-input`, `.btn-link.iw-icon-btn`, `.accordion.iw-accordion` overriding `--bs-accordion-*` vars, etc.) rather than relying on class order. **Any new custom class in bootstrap-app that's meant to override a Bootstrap component's own look should be written as a compound selector (`.bootstrap-class.iw-class`) from the start**, not just `.iw-class` alone.
- Verified live via Playwright screenshots in both apps: full mega-menu flyout, all 3 theme states, mobile nav + nested accordion with rotating chevrons (added to strata-app's accordion buttons to match tailwind/bootstrap's chevron behavior — initially missing, added after noticing the inconsistency), footer layout, announcement bar + payment marquee motion (captured two screenshots a beat apart to confirm actual scrolling, not just static rendering).

## Decisions & why

- **Policy (user-set):** no visual value in the hero (or future sections) may rely on a framework's default/utility value — every font-size, font-weight, and colour must be driven by a token. **Corrected after a real mistake:** the token must be applied through each framework's own native mechanism, not a custom CSS class written the same way in all three (that defeats the point of a framework benchmark). Per app: tailwind-app aliases tokens into `@theme` (`--color-hero-bg`, `--color-heading`, `--color-muted`) so plain Tailwind utilities (`bg-hero-bg`, `text-heading`, `text-muted`, `text-4xl`, `text-lg`) read from them — zero custom CSS. strata-app uses Strata's own arbitrary-value utility syntax (`bg-[var(--x)]`, `text-[var(--x)]` for color, `fs-[var(--x)]` for font-size — Strata's `text-[...]` infers color unless the value ends in a bare length unit, and has no Tailwind-style `type:` hint prefix, so `text-[color:...]`/`text-[length:...]` silently compiles to broken CSS; verified via `strata.output.css` after every change) — zero custom CSS. bootstrap-app overrides Bootstrap's own theming variables where they exist (`--bs-heading-color`, `--bs-secondary-rgb`) and uses native utilities (`bg-black`, `fw-bold`, `text-secondary`) that already matched the token values; only `font-size` on `.hero__title`/`.hero__subtitle` stays a small custom-CSS exception, because raw/unpurged Bootstrap exposes no variable or utility for arbitrary heading/lead font-size — that's a genuine platform limitation, not corner-cutting.
- Hero colour tokens: `--color-bg-hero: #000000`, `--color-text-heading: #ffffff`, `--color-text-muted: #a3a3a3` (raw palette: `--color-black`, `--color-white`, `--color-neutral-400`), plus `--font-weight-bold: 700` — added identically to all 3 `globals.css`. This fixed a real mismatch (tailwind-app was `bg-neutral-950`/`#0a0a0a`, bootstrap/strata were `bg-black`/`#000000`; muted text was `text-neutral-400` vs Bootstrap's `.text-secondary` vs strata's unstyled default).
- Shared font-size/spacing scale (4px base, matches Tailwind's own defaults): `--font-size-xs..5xl` (12/14/16/18/20/24/30/36/48px) and `--space-xs..5xl` (4/8/12/16/24/32/48/64/96px), defined identically by name+value in each app's own `globals.css` `:root` — same names, separate per-app implementation (per user direction, not one shared file/prefix). tailwind-app also aliases them into `@theme inline` (`--text-*`, `--spacing-*`) so Tailwind utilities pull from the same source. bootstrap-app additionally sets `--bs-body-font-size` from `--font-size-md`. **Flagged limitation:** Bootstrap's own utility classes (`fs-1`..`fs-6`, `p-1`..`p-5`, `m-1`..`m-5`) and Strata's `mt-0`..`mt-5` spacing utilities are NOT remapped to this scale — doing so would mean patching vendor CSS (violates the "raw/unpurged Bootstrap" guardrail) or fighting Strata's non-configurable 0–5 utility scale. Consistency is only guaranteed for hand-authored CSS that references these tokens directly, not for each framework's built-in utility classes.
- Shared font family across all 3 apps: **Space Grotesk** (via `next/font/google`, self-hosted automatically by Next — no CDN). Loaded identically in each `layout.tsx` as `--font-space-grotesk`, wired into `body` font-family in each `globals.css`, plus `--bs-body-font-family` override in bootstrap-app so Bootstrap's own components don't diverge. `Geist_Mono` untouched (only sans was inconsistent; mono reserved for future code/mono use). Chosen for the "ink" hero's technical/experimental tone over a neutral corporate sans.
- ai-dev-kit installed once at repo root, not 3x — business-logic JS must stay identical across variants and Step 4's workflow spans all three apps per section, so shared skills/standards/learnings belong in one place. See `CLAUDE.md`.
- Ink cursor is brush-trail-only (blank canvas at rest), not an ambient full-field effect — user explicitly rejected the ambient-field version as too prominent/neon for a background effect.
- Bootstrap tested raw/unpurged intentionally (guardrail from `project-plan.md`) — do not "optimize" `bootstrap-app`'s CSS/JS payload.
- Strata's `bg-dark` resolves to `--st-dark`, which *inverts to light grey in dark theme* by design (same semantic-inversion pattern as Bootstrap's own `--bs-dark`) — this is correct Strata behavior, not a bug. Use `bg-black` (`#000` literal) when true black is wanted, as in the hero.
- Lint (`stylelint`) violations in each app's default `globals.css` (raw hex colors, unordered properties) were left unfixed on purpose — no design-token system exists yet; fixing now would mean inventing tokens prematurely. Revisit in Step 3.
- tailwind-app's theme system: `[data-theme="light"]` / `[data-theme="dim"]` CSS-variable overrides in `globals.css`, defaulting to `[data-theme="dark"]`-equivalent values on bare `:root`. Toggle button in `Header.tsx` cycles `document.documentElement.dataset.theme` via inline Alpine expression (`x-on:click`) — no persistence (localStorage) yet, resets to dark on reload. Removed the old Next.js scaffold `--background`/`--foreground` + `prefers-color-scheme` media query entirely; body background/color now come from the same `--color-bg-hero`/`--color-text-heading` tokens the hero already used.
- **Real Tailwind v4 bug found while building the footer:** `max-w-sm` silently resolved to 8px instead of 24rem, because the project's shared spacing scale (`--spacing-sm` etc., aliased into Tailwind's theme) uses the same tier names (`xs/sm/md/lg/xl/2xl/3xl`) that Tailwind v4's own `max-w-*`/`w-*`/`h-*` utilities read from. Worked around by using `flex-1` instead of a width utility on the affected footer column. This is an unresolved, project-wide naming collision — avoid `max-w-*`/`w-*`/`h-*` utilities whose name matches the spacing scale's tier names anywhere in tailwind-app, and expect the same landmine once bootstrap-app/strata-app get their own Tailwind-style scales (n/a for strata-app/bootstrap-app's own utility systems, but worth checking if either ever layers a Tailwind-like config). See memory note `inkwake-css-token-gotcha`.
- Alpine attributes in JSX/TSX: colon-containing attribute names (`x-on:click`, `x-bind:class`, `:class`) trigger Next's "JSX Namespace is disabled" build error when written as normal JSX attributes. Must be passed via spread syntax: `{...{ "x-on:click": "..." }}`. Plain non-colon Alpine attributes (`x-data`, `x-show`, `x-init`, `x-text`) work fine as normal JSX attributes.
- **Real hydration bug found and fixed:** every element Alpine mutates post-hydration (`x-show` → adds inline `style="display:none"`; `x-text` → overwrites text content; `:class` → adds/removes classes) needs `suppressHydrationWarning`, same as the canvas/`<html>` precedent from Step 2 — otherwise Next's dev overlay silently logs a hydration-mismatch error every load (visible as a "1 Issue" badge in the bottom-left dev overlay, easy to miss if you only screenshot the page and don't check the overlay/console). This had been present since the very first header draft and went unnoticed for a whole session. **Lesson: always check the Next.js dev-overlay issue count (or the terminal dev-server log) after adding any Alpine-driven element, not just a visual screenshot.**

## Don't touch / gotchas

- `bootstrap-app`'s `<body>` has a required `app-body` class — `bootstrap.min.css`'s own `body{font-family:var(--bs-body-font-family)...}` rule loads after our `globals.css` in the compiled HTML (its `<link>` isn't precedence-managed the way Next's own stylesheet is), so a plain `body{}` selector at equal specificity silently loses to Bootstrap's default font stack regardless of what `--bs-body-font-family` is set to. `body.app-body{}` (specificity 0,1,1) beats Bootstrap's plain `body` (0,0,1) regardless of load order — don't drop the class or revert the selector to plain `body`.

- `public/js/ink-cursor.js` is identical across all three apps by design — if you edit one, copy-diff to the other two, don't hand-edit each separately (drift risk).
- `strata-app/package.json`'s `dev` script runs `concurrently` wrapping both `strata:watch` and `next dev` — passing `-p <port>` via `npm run dev -- -p 3002` does NOT reach `next dev` (it's swallowed by concurrently). Use `npx next dev -p <port>` directly for one-off port testing, and run `npm run strata:build` manually first so `public/strata.output.css` is current.
- Background dev servers started via `(cmd &)` in the Bash tool die when that tool call's shell exits — they must be restarted per session tool-window, not assumed persistent. Check `netstat -ano | grep ":<port>"` before assuming a port is free.
