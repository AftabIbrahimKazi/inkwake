# Strata CSS — Learnings

- **2026-08-24 (strata-css ^1.8.17):** `[data-st-visible]` and `[data-st-collapsed]` are core, built-in state attributes (defined in `src/layers/base.js`) with their own baked-in CSS transitions (opacity+translateY fade for visible, max-height collapse for collapsed) — **no plugin/package needed**. Just set the attribute value from your own JS (`element.dataset.stVisible = 'true'`) and Strata's core CSS handles the animation. This is the correct way to build dropdowns/mega-menus/accordions/off-canvas panels in a Strata project — there is no pre-built `.navbar`/`.dropdown-menu`/`.offcanvas`/`.accordion` component in strata-css core (only `Modal`, `Skeleton`, `Chart` ship as real JS components, each pulled from `packages/` only if actually used). Don't go hunting for a Bootstrap-style nav component that doesn't exist — build the interaction with a tiny custom click/hover handler flipping `data-st-*` attributes, and let Strata's own transitions animate it.
- **2026-08-24:** `data-st-theme` genuinely supports `"dim"` as a first-class literal value at the core level (`[data-st-theme="dim"]` selectors exist in `base.js`) — unlike Bootstrap, no shade-splitting workaround is needed to get a working 3-theme (light/dark/dim) toggle. Just cycle the attribute directly.
- **2026-08-24:** `border-color` has **no arbitrary-bracket form** (`coverage.js` lists it under "ONLY named utilities") — for an arbitrary border color, use the full `border-[…]` shorthand (e.g. `border-[1px_solid_var(--x)]`) instead of trying `border-color-[…]` (doesn't exist).
- **2026-08-24:** `grid-template-columns`/`grid-template-rows` arbitrary utilities (`gtc-[…]` / `gtr-[…]`) accept comma-containing values fine, e.g. `gtc-[repeat(4,1fr)]` — commas don't need escaping/underscoring the way spaces do.
- **2026-08-24:** No `a { text-decoration: … }` base-reset rule exists anywhere in Strata's own compiled output (confirmed via grep on `strata.output.css`) — unlike Bootstrap, a project's own `a { text-decoration: none }` reset is safe from Strata's cascade-order and won't need the compound-selector specificity workaround that Bootstrap requires.
- **2026-09-02 (strata-css 1.9.0, upgraded from 1.8.17):** the breakpoint-scoped arbitrary-width no-op (`w-md-[…]` silently emitting nothing, see the old 1.8.17-era workaround) is **fixed** — `coverage.js` now lists `width` with `[arb-bp]  w-lg-[…] w-md-[…] w-sm-[…] …`, and a real build confirms `w-md-\[40%\]` compiles to `@media (min-width:768px){ .w-md-\[40\%\] { width:40%; } }`. After any strata-css version bump, re-run `coverage.js --zero` and diff against comments in the project's CSS claiming "no utility exists" — those claims are version-pinned and go stale silently; this project's `globals.css` had one real hand-written `@media` rule surviving past its fix.
- **2026-09-02 (1.9.0):** confirmed still-genuine gaps (no utility, `coverage.js` returns empty or named-only): `letter-spacing`, `backdrop-filter`, `background-clip`, `animation`, `transition-timing-function` (named keywords only, no arbitrary bracket — so exact `cubic-bezier(...)` curves stay hand-written CSS), `line-height` (only `lh-1`/`lh-base` named, no arbitrary form — exact pixel line-heights like 40px/20px/16px still can't be expressed as a utility).
- **CORRECTION, 2026-09-02 (1.9.0):** this file's Rule #1 ("pseudo-classes/pseudo-elements/state selectors can never become utilities — Strata has no hover: variant syntax") is **stale and now wrong**. 1.9.0 shipped a full variant-prefix system (`node_modules/strata-css/CHANGELOG.md`, "Variant system" entry): `hover:`, `focus`, `focus-visible`, `focus-within`, `active`, `visited`, `target`, form-state (`checked`, `disabled`, `invalid`, …), structural (`first`, `last`, `odd`, `even`, …), pseudo-elements (`placeholder:`, `before:`, `after:`, `marker:`, `selection:`, …), environment (`motion-safe:`, `print:`, …), `rtl:`/`ltr:`, and relational `group-*`/`peer-*` — 45 states + 9 pseudo-elements total, one variant prefix per class token (e.g. `hover:text-primary`, `placeholder:text-muted`). Verified live in this project: `.iw-nav-link:hover`/`.iw-icon-btn:hover` (both `color: var(--color-brand-accent)`) converted cleanly to `hover:text-primary` since `--st-primary` is themed to `--color-brand-accent`; `.iw-theme-toggle:hover` converted to `hover:text-body`; `::placeholder` converted to `placeholder:text-muted`. **What variants still can't do:** arbitrary ARIA-attribute selectors like `[aria-expanded="true"] .child` (not one of the 45 states — no `aria-expanded:` variant), project-defined `[data-active="true"]` values, and reaching a color that only exists as a *different* CSS variable than the base utility uses (e.g. `hover:bg-primary` resolves to `--st-primary`, same as the base `bg-primary` — it can't reach `--st-primary-hover`, so a hover state needing that second variable stays hand-written CSS). **Process lesson:** always re-check version-pinned structural claims (not just per-property coverage) against the installed `CHANGELOG.md`/`README.md` after any strata-css bump — `coverage.js` reports *utility* coverage per property but doesn't surface *variant*-prefix support, which lives in a separate part of the framework.
