# Handover skill — Learnings

- **2026-08-25:** Previous handover.md had grown to 73 lines of dense, run-on paragraphs mixing "why" narrative directly into Current State/Last Session — hard to skim for the actual resume point. Rewrote tighter: moved solved-mystery narrative into terse Decisions bullets (one line: decision — reason), cut anything git already records. Result: 46 lines, same information density, much faster to resume from cold.
- **2026-08-25:** For a session that was mostly *debugging/fixing* (not building new features), the highest-value Decisions bullets were the ones naming the *actual root cause* of a bug that had multiple wrong-turn attempts before the real fix (e.g. "unlayered CSS beats layered utilities" cascade rule, Popper's implicit positioning fallback) — these are exactly the kind of thing a fresh session would rediscover the hard way without a pointer. Worth prioritizing "why did this take 3 attempts" facts over routine "what got built" facts when space is limited.
- **2026-08-27:** A session spanning 3 near-identical builds (same 19 sections, 3 frameworks) produced a LOT of framework-specific root-cause bugs (JIT scanner internals, cascade-layer gotchas, component-stretch quirks). Grouping them under one "Root-cause bugs worth not rediscovering" sub-list inside Decisions (rather than one bullet per bug scattered through the file) kept the section skimmable without losing any of them — worth doing again whenever one session yields >3 same-shaped root-cause findings.
- **2026-09-02:** Session ended with several *superseded* artifacts — two spec docs whose scope shipped upstream mid-session (strata-css 1.9.0). Listing them as a Next-steps decision ("delete or commit — here's the residual value") rather than silently dropping them or leaving them in Current State stopped a fresh session from either re-reading obsolete specs as authoritative or wondering why untracked files were sitting in the root. Worth doing whenever a session's own output gets overtaken by an upstream release.
