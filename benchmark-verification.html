Verification: authenticity of the post-minification benchmark report

Verified 2026-09-03 · scope: 60-run Lighthouse benchmark (bench4) behind report 3 — the strata-app CSS-minification before/after comparison

Claim

Report 3 presents 60 genuine, isolated Lighthouse captures against the live post-minification deployment, with a before/after section claiming Strata's stylesheet transfer dropped 11.5 KB → 8.7 KB gzipped and total page 215.1 KB → 212.3 KB, attributable to the Lightning CSS minification change and not to Tailwind/Bootstrap (both unchanged).

Method

No app UI to drive — the surface is the 60 raw Lighthouse JSON captures, the live production deployment they measured, and the published HTML derived from both. Verified by: raw-file integrity checks, independent re-derivation of every published number from raw JSON with a fresh script, confirming the live site still serves the exact CSS byte-count the report's premise depends on, and re-checking the specific outlier claim in the report's own corrected narrative against the raw trace.

Steps

  1. Counted files across all 6 batch directories — 10/10 each, 60 total.
  2. Hashed all 60 files — 60/60 unique MD5s, no duplicates.
  3. Checked requestedUrl and configSettings.formFactor per file against its directory — 0/60 mismatched.
  4. Checked fetchTime chronology — real 419-second span across the batch, consistent with genuine execution.
  5. Independently recomputed score medians, CSS/JS time medians, stylesheet-byte averages, and total-byte averages from raw files with a fresh script and diffed against the published artifact's embedded data — 6/6 app×mode combinations matched exactly, including the stylesheet-byte figures the before/after claim rests on (Strata mobile: 8876.9 bytes independently computed vs. 8876.9 published).
  6. Curled the live production site — strata.output.css is 26,465 bytes, single-line, no comments, matching the report's premise. Confirmed git log shows the minification commit (19fe072) pushed to origin/dev.
  7. Recomputed the "Tailwind/Bootstrap moved by single-digit bytes" claim independently — deltas were 0.2, 7.1, 5.7, 4.8 bytes across the four mobile/desktop combinations. Claim holds precisely.
  8. Re-pulled the raw trace behind the report's own corrected outlier explanation (Strata mobile run 1, "js≈3111ms... 9 files each ~340ms") → mostly holds, one imprecision found (below).

Findings

  • All underlying data is genuine, correctly attributed, and every published number traces back to the raw captures with zero drift across two independent full recomputations (this report and its predecessor). The live deployment matches the code change the report's entire premise depends on.
  • ⚠ Minor: the report's own outlier explanation says "9 files each ~340ms" — that's the mean, not the actual distribution (which spans 24ms to 492ms, a 20x range). Doesn't change the correctness of the core claim (sum vs. wall-clock), just overstates uniformity in the specific example.
  • No repeat of the "scheduler stall" error from the prior report — the correction that shipped in report 3 is itself accurate under inspection, unlike what it was correcting.
